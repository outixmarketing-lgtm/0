# Airix Cloud — 2.0 (prepared, not deployed)

تحديث لتسجيل الدخول والمزامنة على نفس مشروع Vercel. لا ترفع هذه النسخة قبل تجهيز Supabase ومتغيرات Vercel؛ وإلا ستظهر شاشة إعداد غير مكتمل. النسخة المحلية السابقة ما زالت مستقلة ولم تتغير.

## ماذا تغير؟
- إيميل وكلمة مرور لحساب المالك فقط. لا يوجد تسجيل عام.
- البيانات في PostgreSQL على Supabase، وليست localStorage.
- جلسة الدخول في Cookies محمية HttpOnly / Secure / SameSite=Strict؛ كلمة المرور لا تحفظ في كود الموقع.
- صلاحية المالك تتحقق في API وفي قاعدة البيانات. لا تحتاج service_role أو secret key في هذا المشروع.
- الحفظ لا يعتمد إلا بعد نجاح الشبكة. عند تعديل جهازين لن تُكتب نسخة قديمة فوق الجديدة: يظهر تعارض، ويمكن تنزيل المسودة وتحديث البيانات.
- فحص تحديثات الأجهزة الأخرى كل 30 ثانية وعند الرجوع للنافذة؛ زر «تحديث» يجلبها دون إسقاط نموذج مفتوح تلقائيًا.
- يدعم استيراد النسخة المحلية القديمة من نفس المتصفح أو استيراد نسخة JSON.
- هذه نسخة شخصية صغيرة تحفظ مساحة العمل كسجل JSON واحد، وليست نظامًا كبيرًا متعدد الموظفين. حد البيانات 2MB.

## التفعيل
1. أنشئ/اختر مشروع Supabase مخصصًا. لا تعدّل قاعدة مشتركة دون مراجعة.
2. في Authentication عطّل السماح بالتسجيل العام، ثم أنشئ حساب المالك بإيميله وكلمة مرور قوية يختارها بنفسه. لا ترسل كلمة المرور في الشات.
3. نفذ database/setup.sql، ثم أضف UUID حساب المالك إلى airix_allowed_users كما في آخر الملف.
4. في Vercel > Settings > Environment Variables أضف:
   - SUPABASE_URL: رابط مشروع Supabase.
   - SUPABASE_PUBLISHABLE_KEY: المفتاح العام الذي يبدأ sb_publishable_. لا تستخدم sb_secret_ أو service_role.
   - AIRIX_OWNER_ID: UUID حساب المالك نفسه.
   - APP_ORIGIN: https://0-pink-beta.vercel.app (بدون شرطة ختامية).
5. ارفع ملفات هذه الحزمة إلى نفس مستودع GitHub. راجع عدم وجود تغييرات أحدث قبل الاستبدال.
6. اجعل Framework = Other، وBuild Command = node build-cloud.cjs وOutput Directory = public. أزل تجاوزات الإعدادات القديمة إن تعارضت مع vercel.json. لا يحتاج تثبيت حزم.
7. أعد النشر. تحقق من رفض API للزائر، ثم جرّب الدخول بحساب المالك ومن جهاز ثانٍ.
8. صدّر JSON من التطبيق المحلي أولًا. بعد الدخول للسحابة استورده من الإعدادات، مع تأكيد الاستبدال. لا نحذف النسخة المحلية الأصلية تلقائيًا.

## التشغيل والتحقق
- node test-cloud.cjs: اختبارات API بمحاكاة Supabase، وتشمل رفض الزائر/الحساب الآخر/Origin الغريب والتحقق من بيانات الحفظ وتعارض المراجعات.
- node test-client.cjs: حفظ ناجح، فشل الشبكة، تعارض جهازين وعدم استبدال الحالة عند الفشل.
- node build-cloud.cjs: تجميع الصفحة في public دون نشر ملفات الخادم أو SQL.
- اختبارات التكلفة والمخزون الأصلية موجودة في test.cjs (تخص النسخة المحلية السابقة؛ لا تشغّلها كاختبار لتكامل السحابة).

لا يوجد reset-password آلي في الواجهة الحالية؛ إدارة استعادة كلمة المرور من Supabase. لم تنفذ قاعدة البيانات أو تختبر الجلسات الحقيقية أو معاينة المتصفح حتى يتم توفير الوصول الفعلي للخدمات. الاختبارات المحاكية لا تثبت صلاحية SQL أو RLS الحية. لا تعتبر النشر مكتملًا قبل اختبار حساب غير مسموح ومستخدم غير مسجل ومحاولة حفظ متزامنة على المشروع الحقيقي.
